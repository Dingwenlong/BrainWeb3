# 部署到服务器对外发布（精简演示版）

把 BrainWeb3 作为一个**可登录的公开 Demo** 发布到一台服务器上。一条 `docker compose` 命令拉起全部服务，Caddy 自动签发 HTTPS。

> 范围：前端 + 后端 + EEG 服务 + MySQL。**区块链关闭**（走 mock 网关），**存储用本地磁盘**，**演示账号登录开启**（让访客能直接登入）。
> 这是 Demo，不要放真实/敏感数据。要升级到真正生产，见文末「升级到正式生产」。

---

## 架构（单源反向代理）

```
              ┌─────────────────────── 一台服务器 (Docker) ───────────────────────┐
 浏览器 ──────▶  web (Caddy :80/:443)                                             │
 HTTPS         │   ├─ /            → 静态 SPA（构建好的前端）                       │
               │   └─ /api/*       → reverse_proxy → backend:8080                  │
               │                                                                   │
               │  backend (Spring Boot :8080) ── EEG_SERVICE_BASE_URL ─▶ eeg-service:8101
               │        └── JDBC ─▶ mysql:3306                                     │
               └───────────────────────────────────────────────────────────────────┘
```

前端和 `/api` 同源（都经 Caddy），所以**不需要改任何前端代码、也不用配 CORS**。

涉及文件（都已在仓库里）：
- `apps/backend/Dockerfile`、`services/eeg-service/Dockerfile`、`deploy/web.Dockerfile`、`deploy/Caddyfile`
- `docker-compose.prod.yml`、`.env.production.demo.example`

## 0. 你需要先准备的（只有你能做、需要花钱）

| 项目 | 说明 | 大致成本 |
|---|---|---|
| **一台 Linux 服务器** | Ubuntu 22.04+，**建议 ≥ 4GB 内存 / 2 vCPU / 30GB 盘**（JVM + MySQL + mne 构建较吃内存） | 海外 Hetzner CX22 ≈ €4/月、DigitalOcean/Vultr ≈ $6/月；国内阿里云/腾讯云轻量 ≈ ¥24–34/月 |
| **一个域名**（HTTPS 用） | 公开访问强烈建议 HTTPS，Caddy 需要一个指向服务器 IP 的域名才能自动签证书 | `.top/.xyz` 约 ¥10–60/年（Cloudflare / Namecheap / 阿里云 / 腾讯云） |

> 我无法替你开通服务器或注册域名（要用你的账号 + 付费）。开好之后把 **IP** 和（可选）**域名** 给我，或按下面步骤自己执行。
> 先不想买域名也行：可以先用 `SITE_ADDRESS=:80` 走 `http://服务器IP` 验证，之后随时加域名换 HTTPS。

## 1. 服务器装 Docker（在服务器上执行）

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker     # 让当前用户能用 docker
# 内存只有 2GB 的话，建议加 2GB swap 防止构建 OOM：
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
```

放行防火墙 80 / 443（云厂商安全组也要放行）：

```bash
sudo ufw allow 80,443/tcp 2>/dev/null || true
```

## 2. 拿到代码

```bash
git clone <你的仓库地址> brainweb3 && cd brainweb3
# 或：scp 整个项目目录上去
```

## 3. 配置环境变量

```bash
cp .env.production.demo.example .env.production
# 生成两个强密钥：
openssl rand -hex 32   # 填到 AUTH_JWT_SECRET
openssl rand -hex 32   # 填到 IDENTITY_CREDENTIAL_SECRET
nano .env.production
```

至少改这几项：
- `SITE_ADDRESS` → 你的域名（如 `demo.example.com`）；**先用 IP 测试就填 `:80`**
- `MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD` → 强密码
- `SPRING_DATASOURCE_PASSWORD` → **必须等于 `MYSQL_PASSWORD`**
- `AUTH_JWT_SECRET` / `IDENTITY_CREDENTIAL_SECRET` → 上面生成的 32 字节（64 hex）值

> `.env.production` 含密钥，已加入 `.gitignore`，**不要提交**。

## 4. 域名解析（用 HTTPS 才需要）

到域名服务商把一条 **A 记录** 指向服务器公网 IP：

```
A   demo.example.com   →   <服务器IP>
```

解析生效后，Caddy 会在首次启动时自动申请并续期 Let's Encrypt 证书（要求 80+443 可达）。

## 5. 一键启动

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

> 首次构建会下载 Maven / npm / pip 依赖并编译后端，**约 10–20 分钟**（内存小请确认已加 swap）。
> 想离线/提速可改成 CI 构建镜像，见文末「用 CI 预构建镜像」。

看进度 / 日志：

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f backend   # 等到 "Started ... in N seconds"
```

## 6. 验证

- 浏览器打开 `https://demo.example.com`（或 `http://服务器IP`）。
- 用演示账号登录：`researcher-01` / `owner-01` / `approver-01`，密码 `brainweb3-demo`（即 `AUTH_DEMO_PASSWORD`）。
- 命令行冒烟：
  ```bash
  curl -k https://demo.example.com/api/v1/system/status
  ```

## 运维速查

```bash
# 更新代码后重建并滚动重启
git pull && docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build

# 停止 / 启动
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml --env-file .env.production up -d

# 备份数据库
docker compose -f docker-compose.prod.yml exec mysql \
  sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" brainweb3' > backup_$(date +%F).sql
```

数据持久化在命名卷里：`mysql-data`（数据库）、`backend-storage`（上传文件）、`caddy-data`（证书）。`docker compose down` 不会删卷；`down -v` 才会，慎用。

## 安全说明（公开 Demo）

- 演示账号 + 演示密码登录是**故意开着**的——这是 Demo。别放真实数据。
- 已默认：HTTPS（Caddy）、区块链关闭、本地存储、强 JWT/凭证密钥（你填的）。
- 后端自带 `RuntimeSecurityGuardrails` / `SensitiveTextSanitizer`，但**没有限流**。公开环境建议在 Caddy 层加基础限流，或放到 Cloudflare 后面（免费、自带 WAF/限流/隐藏源站 IP）。

## 升级到正式生产（不再是 Demo）

按需逐项关闭/收口（仓库已有工具）：
- 关演示登录：`AUTH_ALLOW_DEMO_BOOTSTRAP=false`、`AUTH_ALLOW_DEMO_PASSWORD_LOGIN=false`、改强 `AUTH_DEMO_PASSWORD`
- 开真实区块链：`CHAIN_ENABLED=true` + 部署 FISCO BCOS 节点与合约，填 `CHAIN_*` 地址（见 `docs/FISCO 本地联调手册.md`）
- 换对象存储：`STORAGE_PROVIDER=minio` + `MINIO_*`
- 用托管数据库（RDS 等）替换 compose 里的 mysql
- 跑预检：`npm run check:prod-env`；部署后：`npm run smoke:backend -- -BaseUrl https://你的域名`
- 详见 `docs/P5 正式环境联调清单.md` 与 `docs/P5 已知边界与正式环境迁移清单.md`

## 备选：不想管服务器（Railway / Render 等 PaaS）

仓库的 Dockerfile 同样可被 Railway/Render/Fly.io 直接构建。要点：用平台的托管 MySQL；前端与后端分开部署时需要**改用跨域**（给后端加 CORS，或前端设 `VITE_API_BASE_URL` 指向后端域名）。本仓库的 `client.ts` 已支持 `VITE_API_BASE_URL`，缺省走同源 `/api/v1`。免费档通常会休眠、有资源限制，适合临时演示。

## 用 CI 预构建镜像（提速，可选）

在 GitHub Actions 里 `docker build` 三个镜像并推到 GHCR，服务器只 `docker compose pull && up -d`（把 compose 的 `build:` 换成 `image:`）。需要时我可以补一份 `.github/workflows/deploy-images.yml`。
